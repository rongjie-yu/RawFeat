# Low-light Raw feature extractor

The first trained version is [v1](weights/v1/README.md). The preferred checkpoint is [step96000](weights/v1/checkpoint_step_096000.pt), with five-noise H-AUC@5 **68.0846%** against **65.6030%** for MeanAD+SuperPoint on the fixed COCO Raw protocol. The final step100000 and matching-ramp boundary step55000 are included for comparison. [Weight hashes and provenance](weights/v1/manifest.json), [full training analysis](docs/formal_training_analysis_20261007.md), and [validation snapshots](docs/results/v1/) accompany this version.

One current algorithm: [the design](docs/low_light_raw_feature_extractor_design.md). A random student trains for 100000 updates: A detector+gray50000, B matching ramp5000, C joint45000. Detection uses Bernoulli occupancy plus teacher-mass-normalized conditional position (coefficient1); gray has fixed weight10 and epsilon.01. Normal BN, four pairs × accumulation4, FP32, AdamW and global clip5 are shared by both configurations. These stage lengths and gray weight are selected engineering settings, not proven optima.

`configs/formal.yaml` and `configs/smoke.yaml` use the same trainer, schema, losses and schedule functions. Smoke compresses the boundaries to300/100/200, total600. A skips the student descriptor forward, matching and correspondence sampling, and preserves descriptor parameters/BN/Adam. Resume verifies the complete config/code/dependency/data/asset identity and uses the absolute next update and cursor.

To move a run between physical GPUs of the same model, expose one GPU with `CUDA_VISIBLE_DEVICES` and add `--allow-gpu-change` to the resume command. This permits the device mapping change and the exact audited GPU-resume source revision in `rawfeat/gpu_resume_revision.json`; other source, config, hardware model, dependency, data and asset changes remain errors. The original manifest and checkpoint are preserved; each resume records both identities in `resume_identity_*.json`, and future checkpoints carry the current identity. Keep the flag on later resumes of an older run because its original manifest remains unchanged.

The sole entry is `python -m rawfeat.cli`; use `--help` for `preflight`, `train`, `validate`, `diagnose`, `export`, `analyze` and necessary asset preparation. `scripts/run_required_checks.sh` runs tests and read-only preflight, with no training. Logs are per-update JSONL; TensorBoard uses the same fields. Fixed-noise diagnostics distinguish teacher recall, oracle retrieval and automatic homography. `analyze --run PATH` rebuilds raw/smoothed PNG/PDF curves and the final report.

Data, official dependencies and prior results are preserved. [Asset provenance](docs/asset_provenance.md) defines the unchanged InvISP/full-DN/RGGB/noise-stream/MeanAD contracts. [Docs index](docs/README.md) distinguishes the current design from historical evidence (9209 prior updates). Obsolete owned training/BN/candidate routes have been deleted; historical Python is not archived as another executable route.

Preparation, review, bounded smoke evidence and manual commands are recorded in [the preparation report](docs/staged_preparation_report_20261002.md). Full training is launched manually by the user; it is not automatically queued or extended.
