## 已完成的主要发现

1. 原KL的位置监督在有限预算下学习较慢。逐视角教师前景质量归一化显著改善固定clean小集的1px定位、固定K召回和相位排名；三任务自动匹配也改善。这是受控训练证据，已经超出“梯度变大”或“点数更多”的零更新观察。
2. 匹配监督在gray10条件下确实拖慢固定集检测学习；灰度10未被证明是唯一根因。检测+灰度与纯检测的train召回接近，完整三任务仍较低。该条件因果结果不能直接推导出正式训练应删除匹配任务。
3. 新发现并修复ELD实现中的CUDA随机流相关性。当前环境下Poisson与后续共享随机流导致噪声项耦合；各噪声项独立generator消除了实测异常。full-DN曝光模型、标定、黑白电平、WB和噪声单位均保持。它不解释没有ELD噪声的固定clean学习问题。
4. 候选固定集存在明显train/eval差距；诊断使用模型副本，没有BN重估或用train分数替代部署分数。在线和完整噪声协议确认收益，绝对精细定位仍弱；短课程、单种子无法区分全部优化、泛化和表示限制。

## 噪声独立性错误、修复与资产身份

初始噪声矩检查采用15%方差容差，放过了seed11、DN2048、ratio100的+13.19%异常；随后分项协方差复核识别出问题。本轮不再把15%矩容差当作充分依据，改用分项相关性及三seed矩复核，并加入真实CUDA公共接口回归测试。

该条件下，shot+quant与read+row的实测相关为0.11955；原生CUDA `torch.poisson`后共用generator的`torch.rand`在rate55、480×640、seed11/17/101均约0.10，使用独立generator的后续rand接近0。rate1.85及5000的本轮样本未同样异常。这是当前硬件/依赖条件下的观测，不扩展到所有版本。

[PyTorch v2.12.1官方Poisson CUDA源码](https://github.com/pytorch/pytorch/blob/v2.12.1/aten/src/ATen/native/cuda/Distributions.cu#L130)固定推进Philox offset 20并调用curand_poisson；实际Generator offset增量也是20。[普通CUDA随机数源码](https://github.com/pytorch/pytorch/blob/v2.12.1/aten/src/ATen/native/cuda/DistributionTemplates.h#L44)采用另一执行策略计算offset。结合共享/独立流干预，原因指向Poisson的可变随机数消耗与后续随机流重叠；这是源码支持的推断，本轮没有重编或修改PyTorch。

最小修复为read/row/quant各自使用确定派生的独立CUDA generator，保留Poisson seed及所有物理参数。三seed修复后相关绝对值≤0.00217、方差相对误差绝对值≤0.26%；seed11异常从+13.19%降到+0.0586%。没有同时切换曝光模型、限幅、精度或相机映射。没有证据将这个错误作为固定clean定位不足的原因。

保留旧noise源、cache、基线；两个旧在线试验在首个100检查点写完约1.73ms内SIGINT中止，state step100/cursor1600/Adam step100核实。只读gdb附加因ptrace限制失败，没有改变权限；没有调试注入。

噪声改变了数据身份，因此新生成1536对：data.py/sensor.py和clean几何张量不变，clean256份独立字节复制，1280噪声case重新采样ELD。新完整MeanAD基线主分数65.60296854%，旧65.95153886%只作历史；同一manifest仍为v2，cache identity从`568cec...`变为`d950a236...`。formal.yaml仅更新cache/baseline路径，默认检测KL、gray暂存10及未来100k课程保持，不运行正式训练。
